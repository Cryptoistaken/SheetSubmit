SheetSubmit / implementation brief

Make the real interface safer to operate, not merely prettier.

This document records the exact UI fixes applied from the Jakub Krehel skills. The implementation preserves the existing SheetSubmit visual language, uses existing dependencies, and separates high-risk accessibility work from cosmetic polish.

01 / boundaries

Scope and safety rules

Included

  • React shell, login, home tabs, cards, archive, admin, pools, sheet grid, toolbars, overlays, theme and responsive CSS.
  • Accessibility, layout/RTL, copy, typography, colors/tokens, loading/empty states and UI polish.

Excluded

  • Worker routes, Durable Objects, API contracts, Android, production secrets and deployment configuration.
  • No new packages, no new state framework, no broad visual redesign, no speculative refactor.

Agent safety

  • Every agent must inspect the current worktree first.
  • Never use git restore, checkout, reset, or stash.
  • Agents touch only their assigned files and preserve other agents' diffs.

Fix order

  1. Accessibility/data safety
  2. Narrow layout and RTL
  3. Copy and loading
  4. Typography, tokens and polish
  5. Review, verify, commit, push

05 / acceptance

Checks required before delivery

Commands

  • bun run typecheck
  • bun run test
  • bun run build
  • git diff --check
  • Inspect final diff and status.

Interaction

  • Keyboard through login, home, menus, overlays and sheet.
  • Escape closes and restores focus.
  • Run axe/Lighthouse on login, home, pools, admin and sheet.
  • Check reduced motion and forced colors.

Viewport

  • 320px, 375px, 768px and 1280px.
  • 200% zoom and RTL file/user text.
  • Slow 3G loading and empty states.
  • Light/dark theme and safe-area behavior.

Known manual checks

Screen-reader timing, real device notch behavior, rendered contrast values and full RTL mirroring require browser/device verification. Static checks cannot honestly prove those.

06 / delivery

One easy-to-revert delivery

All application fixes and this plan are intended to be delivered in one commit. If the result must be removed, use git revert <commit-sha>; this creates a safe inverse commit without rewriting history.

Before pushing: inspect git status, git diff --stat, git diff --check, the full test/build output, and the exact commit contents. Do not include secrets, generated build output, or unrelated user changes.
